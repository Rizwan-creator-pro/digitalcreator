exportToPDF22(options) — every option documented below
1
Drop the function in
Paste the script into a page-level JavaScript function, or a static application file loaded on every page.
2
Point it at a region
Pass the static ID of the classic report region via pdfRegion — it reads the rendered table directly, no extra query.
3
Call it from a button
Wire it to a Dynamic Action → Execute JavaScript Code on any button, and configure the look through the parameters below.
// Dynamic Action → Execute JavaScript Code
exportToPDF22({
  saveToFile:          "Y",
  pdfRegion:           "PURCHASE-REPORT",
  reportHeadingCustom: "Purchase Report",
  hideColumns:         ["Edit"],
  rightColumns:        ["Total Amount", "Paid Amount"],
  highlightColumns:    ["Total Amount"],
  hideTotalRows:       ["Supplier Total"]
});

Built With

What Powers It

No framework, no build step — vanilla JavaScript reading the DOM directly, on top of two small, focused libraries.

JavaScript (ES6+) jsPDF jspdf-autotable SweetAlert2 Oracle APEX PL/SQL ORDS / REST HTML5 CSS3
Reads the DOM, not a second query
The classic report is already rendered on the page — this pulls straight from that table, so the PDF always matches what the user is looking at.
jsPDF + autoTable for layout
Pagination, column widths, and cell styling are handled by autoTable's hooks — didParseCell and didDrawCell do the per-cell work.
Zero framework lock-in
Plain JavaScript that drops into any APEX page's JS or a static application file — no bundler, no npm install.
